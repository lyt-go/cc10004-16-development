# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 事件参数快照与审计规则绑定

数据审计页可以把「埋点事件 + 审计对象」绑成一条**质量检查记录**（`CHK-xxxx`），
事件详情页的「关联质量检查」引用的就是同一条记录，两处不会各存一份结论。

- **生成**：选择事件与规则后，`frontend/src/api/quality-service.ts` 把参数结构（含字段注释与
  取值口径）、触发条件原文、采样比例及来源页 / 变更人 / 采样轨迹（5%→25% 这类历史）、
  规则的校验字段 / 异常条件 / 审计频率一起写进快照（EVEN-0002 的基线快照是 `snapshot-v7`）。
  快照里的 `ruleBinding` 三条锚点（快照、校验字段、审计频率）必须指向同一事件版本，
  否则不允许生效。
- **生效即冻结**：规则生效时写入快照指纹，基线扫描以「审计对象 + 扫描时刻消息批次」出具第一批异常。
  之后快照只读，页面和后续改版都无法改写。
- **事件改版**：改版只新增事件版本，并给每条已生效快照追加一轮「事件改版」异常；
  旧快照、旧字段注释、旧轮次和旧质量结论原样保留。兼容判断由参数结构差异自动给出
  （必填增删、类型变更、固定口径变更记为不兼容）。
- **并发**：同一「事件 + 规则 + 快照版本」只接受一个生效快照；模拟并发生效时，
  失败一侧只留草稿异常，落库 0 条。
- **生命周期**：`草稿 → 已生效 → 已归档` 单向流转，归档是终点，不能恢复、回退或继续扫描。
- **保留期**：快照自生成起保留 24 个月（`SNAPSHOT_RETENTION_MONTHS`），过期后不能再出具新结论。
- 质量检查数据存在浏览器 `data-product-ops:quality-checks` 里，`resetQualityChecks()` 可重置。
